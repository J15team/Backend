# リファクタリング支援スキル

## アーキテクチャ規約

### フォルダ構成
{層名}/{機能名}/{ファイル名}

### 層と依存ルール
| 層 | 参照可能 |
|---|---|
| domain/ | なし |
| application/ | domain |
| infrastructure/ | domain, application |
| presentation/ | application |

## リファクタリング判断基準

### 構造の問題
- 機能フォルダ内が5ファイル以上で平坦化している
- 層をまたぐ不正なimportがある
- domain層に外部ライブラリ依存がある

### ドメインモデルの問題
- 機能要件に対応するドメインモデルがない
- ドメインモデルに対応する実装がない
- 命名がドメイン用語と乖離している

## 確認手順

1. フォルダ構造を出力して俯瞰
2. 各ファイルのimport文を確認し依存の向きを検証
3. domain層のファイルに外部依存がないか確認
4. 問題点をリスト化し、優先度をつけて提案

## 出力形式

問題を発見した場合：
- **問題**: 何が違反しているか
- **理由**: なぜ問題か
- **修正案**: 具体的なコード or 移動先
- **影響範囲**: 変更による影響
